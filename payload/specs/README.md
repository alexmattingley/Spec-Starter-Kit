# Specs

Plans for changes under active or upcoming work. One folder per feature:
`specs/<area>-<feature-slug>/`.

`agent/` holds the **constitution** — how the codebase works today and what's
planned. `specs/` holds **plans for changing it**. Completed specs stay here as a
historical record of *why* things were built the way they were; for how things work
now, read the constitution and the code.

> **The process, file set, naming, and statuses for specs live in
> [`agent/spec-process.md`](../agent/spec-process.md).** Read that first. New specs
> are scaffolded with `agent/scripts/new-spec.sh <area>-<feature-slug>`.
